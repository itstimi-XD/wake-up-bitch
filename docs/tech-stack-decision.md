# 기술 스택 선택 이유

## 백엔드: NestJS (TypeScript) vs Kotlin Spring

### 왜 NestJS를 선택했나?

#### ✅ 장점

1. **TypeScript 통합**
   - Flutter도 Dart (타입 안전)
   - TypeScript로 프론트-백엔드 모델 공유 가능
   - 타입 에러를 컴파일 시점에 잡음

2. **Clean Architecture 친화적**
   - Dependency Injection이 간단
   - 모듈 시스템이 직관적
   - 레이어 분리가 명확

3. **빠른 개발 속도**
   - NPM 생태계 (패키지가 엄청 많음)
   - Hot Reload 지원
   - Swagger 자동 생성

4. **가볍고 빠름**
   - Node.js 기반으로 메모리 효율적
   - 비동기 처리가 쉬움
   - 서버 시작이 빠름 (1~2초)

5. **비용**
   - 서버 리소스가 적게 듦
   - Heroku, Railway 무료 티어 사용 가능

#### ❌ 단점

1. **타입 안정성**
   - Kotlin/Java보다는 약함
   - Runtime 에러 가능성

2. **대규모 트래픽**
   - JVM보다 성능이 떨어질 수 있음
   - 메모리 누수 주의 필요

3. **멀티스레딩**
   - Node.js는 싱글 스레드 기반
   - CPU 집약적 작업에 불리

---

## Kotlin Spring으로 바꿀까?

### ✅ Kotlin Spring의 장점

1. **타입 안정성**
   - Null Safety
   - 컴파일 타임에 거의 모든 에러 잡음

2. **성능**
   - JVM 기반으로 대규모 트래픽 처리 우수
   - GC 최적화

3. **엔터프라이즈급**
   - 금융, 대기업에서 많이 사용
   - 안정적이고 검증됨

4. **멀티스레딩**
   - Coroutine으로 비동기 처리
   - CPU 집약적 작업 우수

### ❌ Kotlin Spring의 단점

1. **무거움**
   - JVM 메모리 사용량이 큼
   - 서버 시작이 느림 (10~30초)

2. **개발 속도**
   - 설정이 복잡
   - 빌드 시간이 김

3. **비용**
   - 서버 리소스가 많이 필요
   - 무료 호스팅 옵션이 적음

4. **패키지**
   - NPM보다 생태계가 작음

### 결론

**초기 단계: NestJS 추천** ✅
- 빠르게 MVP 만들기
- 무료 배포 가능
- 사용자 피드백 빠르게 받기

**성장 단계: Kotlin Spring 고려**
- 사용자 10만 이상
- 안정성이 매우 중요
- 충분한 서버 예산
